# 배포 서버에 백엔드 올리기 (동아 클라우드 VM)

학교 클라우드(https://cloud.dauai.org)에 VM을 하나 만들고 백엔드를 올려, 휴대폰 앱이 어디서든 `https://<VM이름>-<아이디>.apps.dauai.org`로 서버를 부르게 하는 방법이다. 시연도 이 서버로 할 수 있다.

- VM 만들기·접속은 교수님이 주신 "동아 클라우드 서비스 간단 안내"(DHub Getting Started)를 따른다. 아래 1·2는 그 요약이다
- 서버는 VM이 켜질 때 자동으로 뜨고, 죽으면 5초 뒤 다시 뜬다 (`deploy/jeonse-backend.service`)
- DB는 시연까지 SQLite(`backend/data/jeonse.db`)다. 설정은 `backend/.env` 하나에 있다 (git에 올리지 않음)

## 1. 계정과 VM (한 번만)

| 할 일 | 방법 |
| --- | --- |
| 계정 신청 | https://cloud.dauai.org → "계정 신청". 메일은 `donga.ac.kr`이나 gmail (`dau.ac.kr`은 안 됨) → 인증 메일의 링크 → 운영자 승인 메일이 오면 로그인 |
| VM 만들기 | VM → "VM 생성". 노드는 "자동", 이름은 영문 소문자(예: `jeonse`, 주소에 들어감), OS는 Ubuntu 24.04, 유형은 **S (2 vCPU · 4GB)**, 디스크 32GB, GPU 없음 |
| ssh 키 | VM 목록에서 VM을 눌러 상세 화면 → "키 받기" → `C:\Users\<사용자>\.ssh\`(macOS `~/.ssh/`)에 둔다. **키 파일은 남에게 주지 않는다** |
| VS Code 접속 | 확장 "Remote - SSH" 설치 → 왼쪽 아래 `><` → Connect to Host → Configure SSH Hosts → `.ssh\config`에 상세 화면의 `~/.SSH/CONFIG` 내용을 붙여 넣고 저장 → 다시 Connect to Host에서 VM 이름 선택 (OS는 Linux) |

배포 주소는 VM 상세 화면 "앱 → 웹"에 나온다 (`https://<VM이름>-<아이디>.apps.dauai.org`).

## 2. 백엔드 설치 (한 번만)

VS Code로 VM에 접속한 터미널에서:

```bash
git clone https://github.com/polopy07/jeonse_companion.git
cd jeonse_companion
bash deploy/setup_vm.sh https://<VM이름>-<아이디>.apps.dauai.org
```

`setup_vm.sh`가 하는 일 (여러 번 돌려도 된다. 이미 있는 `backend/.env`와 DB는 건드리지 않음):

1. 파이썬 가상환경(`.venv`)을 만들고 `backend/requirements.txt` 설치 (`python3-venv`가 없으면 `sudo apt`로 설치)
2. `backend/.env` 만들기: SQLite, 결제·접근 토큰 필수(`REQUIRE_CONTRACT_AUTH=true`), 시연용 가상 날짜 허용(`ALLOW_VIRTUAL_TODAY=true`), 관리자 토큰(`ADMIN_TOKEN`, 무작위로 만듦), 배포 주소(`PUBLIC_BASE_URL`, 캘린더 구독 링크에 씀), 메일은 `console`(보내지 않음)
3. 시연 DB 만들기 (`reset_demo_db.py`: 시연 집 실거래 저장본 180건)
4. 자동 실행 등록: `/etc/systemd/system/jeonse-backend.service` → `systemctl enable --now`
5. `http://127.0.0.1:8000/health` 확인

마지막에 `{"status":"ok",...}`와 "서버가 떴습니다"가 나오면

6. VM 상세 화면 "앱 → 웹"의 **포트에 `8000`을 넣고 저장**
7. 브라우저로 `https://<배포 주소>/health`를 열어 `{"status":"ok"}` 확인

## 3. 앱을 배포 서버에 연결

`frontend/.env.local`의 서버 주소만 바꾼다 (휴대폰이 PC와 같은 와이파이에 있지 않아도 된다).

```
EXPO_PUBLIC_API_URL=https://<VM이름>-<아이디>.apps.dauai.org
```

바꾼 뒤 `npx expo start`를 다시 띄운다 (주소는 시작할 때 읽음). 앱 실행 방법은 `docs/guide/휴대폰_접속_방법.md`.

## 4. 설정 바꾸기 (`backend/.env`)

VM에서 `backend/.env`를 고치고 `sudo systemctl restart jeonse-backend`. 항목 설명은 `backend/.env.example`.

| 하고 싶은 것 | 바꿀 값 |
| --- | --- |
| 알림 메일 실제 발송 (Gmail) | `EMAIL_BACKEND=smtp`, `SMTP_HOST=smtp.gmail.com`, `SMTP_PORT=587`, `SMTP_USER`·`SMTP_FROM`=보내는 주소, `SMTP_PASSWORD`=**앱 비밀번호**(Google 계정 → 보안 → 2단계 인증 → 앱 비밀번호, 계정 비밀번호 아님). 시연용 Gmail 계정을 따로 쓰는 것을 권함 |
| 관리자 API (알림 실행·경보 재계산) | 요청 헤더 `X-Admin-Token`에 `.env`의 `ADMIN_TOKEN` 값 |
| 실거래가를 새로 받기 | `DATA_GO_KR_SERVICE_KEY` (시연은 저장본이라 필요 없음) |
| 시연이 끝나면 가상 날짜 끄기 | `ALLOW_VIRTUAL_TODAY=false`. 공개 주소라 `true`면 누구나 `X-Virtual-Today`로 날짜를 바꿔 부를 수 있다 (시연 때만 `true`) |
| 접근 링크 메일에 링크 넣기 | `APP_LINK_BASE`. 메일 링크는 `{APP_LINK_BASE}?contract=…&token=…`이라 앱의 "내 계약 불러오기"(`/load-contract`) 경로까지 넣는다. Expo Go면 `exp://<노트북 IP>:8081/--/load-contract`(노트북 IP가 바뀌면 다시), 앱으로 빌드하면 `jeonsecompanion://load-contract`. 비워 두면 메일에 계약 번호와 접근 코드만 가고, 앱에서 직접 넣는다 |

`.env`에는 비밀번호·토큰이 들어가므로 채팅·노션·git에 붙여 넣지 않는다 (`setup_vm.sh`가 본인만 읽게 `chmod 600`).

## 5. main 최신으로 바꾸기 · 시연 DB 초기화

```bash
cd ~/jeonse_companion
bash deploy/update.sh          # 코드만 바꿈 (DB·증빙 사진은 그대로)
bash deploy/update.sh --reset  # 시연 DB도 초기화 (판정·계약·할 일·증빙을 모두 지움). 리허설·시연 직전
```

`update.sh`는 `git pull` → 패키지 → 서버를 끄고(`--reset`이면 이때 초기화) 다시 켜고 `/health`까지 확인한다. 앱에 저장해 둔 예전 계약은 서버에 없으면(404) 앱이 지운다.

## 6. 서버 관리 명령

| 하고 싶은 것 | 명령 |
| --- | --- |
| 상태 | `systemctl status jeonse-backend` |
| 로그 (최근 50줄 / 계속 보기) | `journalctl -u jeonse-backend -n 50 --no-pager` / `journalctl -u jeonse-backend -f` |
| 다시 띄우기 | `sudo systemctl restart jeonse-backend` |
| 멈추기 / 자동 실행 끄기 | `sudo systemctl stop jeonse-backend` / `sudo systemctl disable jeonse-backend` |

## 문제가 생기면

| 증상 | 확인할 것 |
| --- | --- |
| `setup_vm.sh` 끝에 "서버가 뜨지 않았습니다" | `journalctl -u jeonse-backend -n 50 --no-pager`. 패키지 설치 오류면 `.venv/bin/pip install -r backend/requirements.txt`를 다시 |
| VM 안에서는 `/health`가 되는데 브라우저에서 안 열림 | VM 상세 화면 포트가 `8000`으로 저장됐는지. 서버는 `--host 0.0.0.0`으로 떠야 함 (서비스 설정에 들어 있음) |
| 앱에서 "서버에 연결하지 못했어요" (또는 "앱에서 임시로 계산했어요") | `frontend/.env.local` 주소가 `https://`로 시작하고 끝에 `/`가 없는지, 바꾼 뒤 `npx expo start`를 다시 띄웠는지 |
| 앱에서 계약이 404 | `update.sh --reset`으로 DB를 지우면 예전 계약이 없어짐. 앱에서 계약 전 확인부터 다시 |
| 메일이 안 감 | `EMAIL_BACKEND=smtp`인지, 앱 비밀번호(띄어쓰기 있어도 됨)인지. 로그에서 `SMTP` 오류 확인. `console`이면 보내지 않는다 |
| 캘린더 구독 주소가 `http://`이거나 배포 주소가 아님 | `.env`의 `PUBLIC_BASE_URL`에 배포 주소를 넣고 다시 띄우기 |
| 큰 사진이 안 올라감 | 서버가 증빙·서류 사진은 20MB(`app/evidence.py` `MAX_EVIDENCE_BYTES`), 등기부 PDF는 10MB까지 받는다. 학교 프록시 앞단의 크기 제한은 우리가 정할 수 없어 서버 제한으로 막는다 |
| 패키지 설치가 파이썬 버전 때문에 실패 | Ubuntu 24.04 기본은 파이썬 3.12, CI는 3.13. 오류 메시지를 팀에 공유 |
