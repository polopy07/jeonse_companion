**목차**

1\. 문서 개요 (Introduction)

1.1 목적 (Purpose)

본 문서는 전세 세입자용 서비스 「전동기」의 MVP가 갖춰야 할 기능·비기능·데이터·AI 요구사항을 테스트 가능한 문장으로 정의한다. 설계, 구현, 테스트(검증 계획 3개 항목과 사용성 테스트)의 기준 문서로 쓴다.

- 대상 독자: 팀원(PM·PO, 개발 A 백엔드·규칙, 개발 B 프론트·검증), 검토자

1.2 프로젝트 범위 (Scope)

**해결하려는 문제**

1.  전세 계약 후 할 일이 사람마다 다르고 서로 연결돼 있다 (대출 여부, 보증기관, 신고 대상 여부, 점검 결과, 계약서에 넣은 특약, 잔금일 변경, 2년 뒤 다음 집과의 날짜 맞추기).

2.  보증금을 못 돌려받는 순간에야 청구 서류를 찾는다.

3.  계약 전에는 집값 대비 보증금 위험을 알기 어렵고, 계약 후에는 집값이 떨어져도 알려 주는 곳이 없다.

**핵심 서비스**

| **구분** | **기능**                                                                                                             | **제공 방식** |
|----------|----------------------------------------------------------------------------------------------------------------------|---------------|
| 메인 ①   | 맞춤 할 일 (할 일 9종 + 갈아타기)                                                                                    | 패키지        |
| 메인 ②   | 전세 기록함 (증빙 사진, 계약 타임라인, 반환 대응)                                                                    | 패키지        |
| 메인 ③   | 역전세 경보 (계약 전 지표 무료, 계약 중 재계산 패키지)                                                               | 무료 + 패키지 |
| 보조     | 사전 권리 점검(등기부 요약 해석, 위반건축물), 계약 당일 체크(현장 확인, 특약 예시, 특약 반영 여부 기록), 알림·캘린더 | 무료 / 패키지 |

**MVP 목표**: 부산의 집 두 채(근저당이 있는 다세대 빌라, 아파트)로 계약 전 확인 → 판정 → 계약 당일 체크 → 맞춤 할 일 → 기록함 → 만기·갈아타기 흐름을 가상 날짜로 5분 안에 시연한다. 시연에서는 빌라의 담보 설정 금지 특약을 "거절당함"으로 골라 할 일 순서가 바뀌는 장면을 보여 준다.

**범위 제외 (MVP)**

- 실제 결제 (테스트 모드만), 웹 푸시, 계약서 OCR, 주민번호 자동 가림, 가족 공유 링크, 다가구 위험 점검

- 주소 기반 공시가격·건축물대장 자동 조회 (시연 집 2채만 사전 매칭, 그 외는 직접 입력)

- 실시간 실거래가 API 연동 (아파트 1개 단지 CSV 파일만 사용)

- 이메일 알림은 1종(반환보증 가입 마감)만 실제 발송

- 연동 규칙 6개 중 3개(근저당, 보증금 비율 90% 이상, 신탁등기)만 구현

- 특약 반영 분기 3개 중 2개(담보 설정 금지, 보증·대출 거절 시 계약 해제)만 구현

**서비스 범위 밖 (본 서비스 포함)**

- 개별 법률 판단, 계약서 법률 검토, 시세 감정평가

- 보증·대출 심사와 청구 처리, 대출 상품 추천

- 다가구·단독주택의 등기부 점검과 역전세 경보

2\. 전체 설명 (Overall Description)

2.1 제품 관점 (Product Perspective)

전동기는 독립형 모바일 웹 서비스(PWA)다. 공공기관·보증기관 시스템과 API로 직접 연동하지 않고, 공공 데이터 파일과 사용자가 올린 자료로 계산한 뒤 공식 창구는 링크로 연결한다.

| **외부 요소**                                                         | **관계**                                              |
|-----------------------------------------------------------------------|-------------------------------------------------------|
| 인터넷등기소                                                          | 사용자가 직접 열람(700원, 사용자 부담)한 PDF를 업로드 |
| 공동주택 공시가격, 건축물대장, 국토교통부 실거래가                    | 공공 데이터 파일을 서버에 적재해 계산에 사용          |
| LLM API                                                               | 등기 항목 설명, 할 일 안내 문구 생성                  |
| 이메일 발송 서버                                                      | 기한 알림 발송                                        |
| 구글·애플 캘린더                                                      | ICS 파일 내보내기                                     |
| HUG 안심전세앱, 보증기관 청구 창구, 대법원 전자소송, 대한법률구조공단 | 안내 문구와 링크로만 연결                             |

2.3 운영 환경 (Operating Environment)

- **Client:** 모바일 웹(PWA) — iOS Safari, Android Chrome 최신 버전 / 데스크톱 Chrome·Edge 최신 버전

- **Frontend:** React

- **Server:** Linux / Docker, Python FastAPI, APScheduler(알림·재계산 스케줄러)

- **External AI/API:** LLM API (모델 미정), 이메일 발송(SMTP)

- **Database:** PostgreSQL (사용자·계약·할 일·판정·경보 이력), 객체 스토리지 (증빙 사진, 암호화 저장). 벡터 DB는 사용하지 않음

- **문서 처리:** pdfplumber (등기부 PDF 텍스트 추출)

2.4 제약사항 (Constraints)

- 부산 지역 데이터의 출처와 이용조건을 명시한다. 시연 집 2채와 실거래 CSV 모두 부산 기준이다.

- 개인정보 수집을 최소화한다. 주민등록번호는 수집하지 않고, 주민번호가 보이는 서류는 사용자가 가린 뒤 올리도록 안내한다.

- LLM 단순 1회 호출로 구성하지 않는다. 등기부 처리는 "PDF 추출 → 규칙 파서 → 사용자 확인 → 규칙 판정 → LLM 설명 → 금지 표현 검사"의 다단계로 구성하고, 기한·비율 계산은 LLM이 아닌 규칙 엔진이 맡는다.

- 실제 결제는 범위 밖이며, MVP는 결제 테스트 모드만 둔다.

- 개발 인원 2명, 기간 4주. 2주차 끝 중간 점검에서 기준 미달이면 3주차 범위를 줄인다.

- 결과는 판정이 아닌 정보로 표시한다. "안전합니다" 표현, 개별 법률 판단, 대출·보증 상품 추천을 하지 않는다.

- HUG·HF·SGI의 이름·로고를 공식 서비스처럼 쓰지 않고 "제도 안내"로만 표기한다.

- 등기부 열람 비용(1건 700원)은 사용자가 부담한다.

2.5 가정 및 의존성 (Assumptions & Dependencies)

- 사용자가 인터넷등기소에서 등기부를 직접 열람해 PDF로 올린다고 가정한다.

- "주요 등기사항 요약" 페이지 양식이 개발 기간 동안 바뀌지 않는다고 가정한다.

- 공시가격은 연 1회 공시되고, 실거래 신고는 계약 후 최대 30일 뒤 공개된다. 경보 정확도는 이 갱신 주기에 의존한다.

- 추정 주택가격 산식(공시가격 × 140%)은 HUG 반환보증 심사 방식을 따른다고 가정한다.

- LLM API와 이메일 발송 서버가 정상 제공된다고 가정한다. 실패해도 판정·할 일 기능은 동작해야 한다 (AI-REQ-04).

- 판정 기준, 경보 기준, 가격(9,900원/4,900원)은 팀 가설이며 검증 결과와 MVP 이후 이용 데이터로 바뀔 수 있다.

- 출시 전 외부 확인이 필요한 항목: HF·SGI 반환보증 가입 기한과 기산일, HUG 전세보증 사전심사(2026-10-30 시행 예정)의 실제 기준, 신고 비대상 계약의 사전심사 가능 여부, 특약 예시·특약 거절 시 위험 안내·계약 당일 현장 확인 목록·전입 경고·계약갱신요구권 안내 문구의 법률 표현 범위, 서비스명 "전동기"의 상표·앱 이름 중복 여부.

3\. 기능 요구사항 (Functional Requirements)
