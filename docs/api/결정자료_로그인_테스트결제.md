## 둘을 같이 정하면

추천안(#39 A + #40 B)으로 가면 흐름은 이렇게 된다.

1. 계약 전 확인 (로그인 없음) → 판정
2. 테스트 결제 `POST /api/checks/{id}/payment` → `payment_id`
3. 현장 확인·특약 (화면)
4. 계약 생성 `POST /api/contracts` (`payment_id` 포함) → 계약 + 할 일 + **`access_token`**
5. 이후 계약·할 일 요청은 모두 `X-Contract-Token`

일정: 백엔드 1.5일(황웅재, 10/17~10/20), 앱 1일(배승환). 2주차 중간 점검(10/20) 전에 백엔드를 끝내고 앱 연결은 3주차 초. 순서는 결제 → 토큰 (토큰이 결제보다 앱 수정이 많음)
