# 등기부 요약 추출 정확도 (중간 점검)

- 기준: 검증 샘플 10건, 항목 기준 95% 이상 (기획서 v4.35 검증 계획, 중간 점검 2026-10-20). 미달이면 수동 입력 중심으로 바꾸고 특약 분기를 1개로 줄인다
- 측정일: 2026-10-14, 파서: main(`backend/app/registry/parser.py`, #62·#65·#70 반영)
- 결과: **112 / 112 항목 = 100%, 통과** (PDF에서 잘려 보이지 않는 이름 1개는 채점에서 뺌. 이것까지 틀린 것으로 세면 112 / 113 = 99.1%)

## 측정 방법

1. 샘플 10건: 인터넷등기소 "부동산정보요약" PDF를 `app/registry/pdf.py`로 뽑은 글자를, 집·사람을 찾을 수 없게 이름·주소·번호를 바꾼 것 (`backend/tests/fixtures/registry/`, 바꾼 기준은 그 폴더 README)
2. 정답표: 사람이 각 원문을 읽고 적은 값 ([`registry_answers.yaml`](registry_answers.yaml)). 파서 결과를 옮겨 적지 않았다
3. 채점: [`backend/measure_registry_accuracy.py`](../../backend/measure_registry_accuracy.py)가 파서 결과와 정답을 항목별로 대조한다

| 항목 | 맞는 조건 |
| --- | --- |
| 소유자 | 이름마다 1항목. 이름이 같아야 함 |
| 갑구 등기 | 순위번호마다 1항목. 종류(압류·가압류·가처분·경매 / 신탁)가 같아야 함 |
| 을구 근저당 | 순위번호마다 채권최고액·근저당권자 2항목 |
| 을구 전세권·임차권 | 순위번호마다 등기목적·보증금·권리자 3항목 |
| 판정 입력 5칸 | 압류 등 유무, 근저당 유무, 채권최고액 합계, 임차권·전세권 보증금 합계(같은 보증금은 한 번만), 신탁 유무 |
| 잘못 찾은 것 | 정답에 없는 소유자·등기를 읽었거나, 분류하지 못하고 사용자 확인으로 넘긴 등기는 1개마다 틀린 항목 1개 |

## 한계 (중간 점검 때 같이 말할 것)

- **이 10건은 파서를 만들면서 맞춰 본 샘플이다.** 정규식을 이 샘플들에 맞게 고쳤으므로 100%는 "처음 보는 등기부"의 정확도가 아니다. 처음 보는 등기부 3~5건을 더 받아 정답표에 넣고 다시 재면 더 믿을 만한 값이 된다
- PDF에서 글자를 뽑는 단계(`pdf.py`)는 샘플을 만들 때 실제 PDF로 거쳤지만, 원본 PDF를 저장소에 넣지 않아 이 측정에서 다시 돌리지는 않는다. 이름을 바꾼 것 외에 글자 모양(줄 나뉨, 붙은 이름)은 PDF에서 뽑은 그대로다
- 신탁 주의사항은 종류(신탁)만 본다. 등기목적 원문("약정/금지사항/환매특약")은 PDF에서 행 위아래로 갈라져 파서가 "신탁 주의사항"으로 이름을 붙인다
- 근저당 변경 부기(1-1 등)는 부동산정보요약에 따로 나오지 않아 샘플에 없다. 증명서의 "주요 등기사항 요약"에 나오면 파서는 합계에 넣지 않고 사용자 확인으로 넘긴다

## 다시 재는 법

```bash
cd backend && python measure_registry_accuracy.py
```

`tests/test_registry_accuracy.py`가 매번 같은 계산으로 95% 이상인지, 틀린 항목이 새로 생기지 않았는지 검사한다. 샘플을 더하면 `registry_answers.yaml`에 원문을 읽고 적은 정답을 함께 넣는다.
