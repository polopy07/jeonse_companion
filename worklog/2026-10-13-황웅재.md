## 결정한 것과 이유
- 관리자 API는 `ADMIN_TOKEN`으로 막고, 서버에 토큰이 없으면 꺼 둠. 한 번 수집에 공공데이터포털을 최대 96번 부르므로 배포 서버에서 누구나 부르면 인증키 하루 호출 한도를 다 쓸 수 있어서 (이슈 #55와 같은 내용)
- "문제 항목" 판정은 특약 예시도 주지 않음(409). 특약만 넣으면 진행해도 된다고 읽히지 않게. 프론트(#29)도 같은 기준으로 계약 당일 화면에서 막음
- 대출 실행일을 모르면 5번 시작일은 전입신고 다음 날. 대출이 없을 때와 같은 기준이고, 반환보증은 전입신고 뒤에 가입할 수 있어서. 정답표에는 아직 시나리오가 없음
- 쓰지 않는 표현 검사는 화면 문구만. 내부 설명에 법령·공공 자료를 인용할 때 오탐하지 않게
- 등기부는 인터넷등기소 "부동산정보요약"을 PDF로 저장해 올리게 함(파서는 증명서의 "주요 등기사항 요약"도 읽음). 열람 PDF에는 요약이 없고, 본문은 말소된 줄이 취소선이라 글자만으로는 유효한 권리를 가리기 어려워서
- 시연 빌라는 근저당이 있고 소유자가 1명인 집으로. 공동 소유면 현장 확인 화면이 소유자 1명만 대조하고, 근저당 없으면 담보 설정 금지 특약 장면이 안 나와서
- 시연 아파트는 근저당 없는 세대로. 근저당 있는 세대는 시세 보증금이면 100%를 넘어 결제 전 멈춤이 되고, 빌라(근저당·특약 거절)와 다른 장면(문제 항목 없음 + 경보 주의)을 보여 줄 수 있어서
- 시연 빌라 근저당은 가상(1,440만). 실제 열람한 집은 근저당이 없거나 집값을 크게 넘어, 비율 90~100%(특약 분기 2개가 함께 나오고 결제는 막히지 않는 구간)를 맞출 수 없어서. 단지·공시가격·실거래·등기부 구성은 실제 자료, 화면·시연 자료에 "시연용 가상 근저당" 표시. 규칙(담보 설정 금지 특약은 근저당 있을 때만)은 #29 리뷰 결정대로 둠
- 저장소에는 실제 세대(호수)를 적지 않고 등기부 주소는 가상으로. 실제 세대에 가상 근저당을 붙인 등기부가 공개되지 않게
- 로컬 DB는 모델이 바뀌면 다시 만들고, 마이그레이션 도구(Alembic)는 배포 서버에 데이터가 쌓이기 시작할 때 들임. 배포 전이라 지울 데이터가 없어서
- 을구 임차권·전세권 보증금은 선순위 채권에 자동으로 더하고 확인 화면에서 뺄 수 있게 (PO). 앞 세입자 보증금은 새 세입자보다 먼저 돌려받는 돈이라 놓치면 비율이 실제보다 낮게 나오고, 이미 돌려받았거나 내 계약일 수 있어 사용자가 뺄 수 있어야 해서
- 실제 등기부 샘플은 집을 찾을 수 없게 바꿔 올림(층·호·면적·날짜·청구금액·기관 이름). 경매·공매 정보가 공개라 이름을 가려도 나머지 값으로 집과 소유자를 찾을 수 있어서. 판정·합계와 글자 모양은 그대로 둬 파서 검증에는 영향 없음
- 이미 푸시된 예전 커밋은 그대로 두고 저장소도 공개로 둠. 등기부는 누구나 열람할 수 있는 자료이고 이름·주민번호는 처음부터 가렸으며, 비공개 전환·기록 다시 쓰기(쌓인 PR 4개)보다 부담이 작아서. 앞으로 올리는 샘플은 처음부터 바꾼 값으로
- 같은 보증금이 전세권·임차권으로 함께 있으면 한 번만, 못 돌려받은 금액(임차권)을 셈 (PO). 등기부가 직접 밝힌 남은 금액이 정확하고, 전세금(큰 쪽)을 세면 이미 돌려받은 만큼 비율이 부풀려져서. 자동으로 묶되 확인 화면에서 다시 넣을 수 있게 해 오판을 사용자가 고칠 수 있게
- 근저당권 변경 부기는 따로 처리하지 않음. "부동산정보요약"은 지금 유효한 근저당만 보여 주고 변경 부기를 따로 나열하지 않아서 (실제 샘플로 확인)
- 시장 규모의 부산 건수는 인구 비중 가정 대신 실거래 집계로. 신규 계약 기준 건수도 함께 적음. 패키지가 계약 당일부터 관리하므로 갱신 계약(약 21%)은 주 대상이 아니라서
- #62 이전 커밋이 든 브랜치(#64, #65·#68·#70, #67·#71)는 squash로 병합. #62를 squash로 넣은 이유(값을 바꾸기 전 샘플을 main 기록에 남기지 않음)와 같고, 쌓인 PR은 맨 위 하나(#70)로 합쳐 승인을 한 번만 받음
